命令卡片

机器人的全部命令与用法。群聊命令在机器人所在群里发送（@机器人 直接说话是 AI 对话，需在 ai 段开启）；每条群命令都能在 config.yml 的 commands 段单独开关，关掉后 /菜单 里的按钮与 QQ 快捷面板按钮会同步消失。

群聊命令 · 所有人可用

命令功能与用法
/菜单输出全部可用命令的按钮菜单（替代原 /帮助）：长按钮（超过 3 字，如玩家名片 / 在线排行榜 / 切换服务器等）独占一行放在最上面，短按钮（不超过 3 字，含「AI管理」）一行两个，全部命令分页展示；无参数命令（查在线 / 在线排行榜 等）点一下即直接执行并回复结果，需要补参数的命令（绑定 / 发信息 / 执行命令 / 执行 / 管理员执行）点击复制到输入框，补全内容后发送；命令多时点「下一页」翻页；管理类按钮的权限在按钮上直接判定（qq/both 下仅群主/群管理员可点，名单模式下点击填入输入栏手动发送）
/玩家名片/玩家名片 @成员查询自己的玩家统计卡片（游戏时长、金币、点券、称号、皮肤等）；@某成员 可查对方的卡片；一个 QQ 绑定了多个玩家时先点按钮选择（旧客户端可回复数字）
/查在线别名 /在线查看在线玩家列表与皮肤头像；默认输出图片卡片，想换成文字列表见「查在线输出」设置
/查性能服务器性能卡片：TPS、MSPT、内存、CPU 与右上角综合状态
/在线排行榜全服在线时长排行榜（图片分页展示）
/财富榜金币排行榜；服务器需安装 Vault 经济插件，未装时提示不可用
/签到别名 /sign每日签到领取奖励（金币、点券等；连续签到有加成）；需要开启 QQ 绑定与签到两个开关；一个 QQ 绑定了多个玩家时先回复数字选择给谁签到
/绑定 <绑定码>用进服时收到的数字验证码绑定 QQ 与游戏账号；在群里直接发送纯数字验证码效果相同
/重新绑定解除自己的绑定（会同时踢下线），下次进服重新获取验证码；换 QQ 号时用
/查信息查询自己的 OpenId 与群 OpenId（配置群白名单、管理员名单用）；后面接玩家名可反查该玩家绑定的 QQ 账号与其名下全部绑定玩家（如 /查信息 Steve，QQ 号行全员可见）；也可 /查信息 @成员 查看成员绑定信息
/切换服务器 [服务器名]多服务器集群：查看当前连接本机器人的全部服务器并点击按钮切换；带服务器名发送可直接切换（如 /切换服务器 生存服；「全局」为特权目标需管理员，按钮同样仅管理员可点）（未配置集群时提示单服；配置方法见「多服务器集群」设置）
/发信息 <内容>把一句话发送到游戏内全服聊天，如 /发信息 大家好
/执行 <key>触发服主预设的自定义命令（见「自定义指令」设置）

群聊命令 · 管理员

管理员默认为群主与群管理员（admin.mode: qq），也可改配置名单判定，见「命令与管理」设置。

命令功能与用法
/执行命令 <命令>在群里远程执行服务器命令，执行结果原样回传（超长自动截断），如 /执行命令 say 大家好
/管理员执行 <key>以管理员权限触发自定义命令（预设里 permission 非 0 的条目）
/黑名单 @成员把成员拉黑并解绑踢出（无法再进服）；不带参数发送则查看黑名单列表（每个条目带「解除」按钮，点击即移出）
/解除黑名单 @成员把成员移出黑名单；不带参数发送则查看列表——发送 /解除黑名单 @对应的人 解除，也可以点击列表下方对应的「解除」按钮（逐条竖排）解除
/认证查看自己的认证状态；管理员发送 /认证 @成员 或 /认证 <OpenId> 可标记他人
/解除认证 <OpenId>撤销成员的认证状态
/全量开 / 关全量转发总开关（对 bot.groups 里全部群统一生效，切换后写回 config.yml）
/AI管理 开|关|清除AI 上下文管理（合并原「AI对话上下文」「清除当前上下文」两条命令）；不带参数发送则查看当前状态并弹出三个按钮（一行一个）：开启上下文 / 关闭上下文 / 清除上下文，点击即执行；AI 功能关闭时本命令不可用

游戏内与控制台命令（OP）

插件版与模组版命令相同；主命令 /hbkrg 需要 OP 权限。

命令功能与用法
/hbkrg reload重载配置并重新同步 QQ 快捷指令面板；机器人凭据（bot.app-id / secret）与更新检查两项必须重启服务器才生效
/hbkrg info查看插件版本与运行平台
/hbkrg chsQQ 机器人掉线或重连挂起时，手动重连一次
/hbkrg mem查看插件内存诊断（JVM 堆与各级图片缓存占用）
/hbkrg bpng列出官网可下载的背景图片包；/hbkrg bpng <包名> 下载指定图片包；/hbkrg bpng stop 中断进行中的下载
/hbkrg bpngsz yes|no一键开关统计卡片的随机背景图（yes 开 / no 关，自动写回配置）
/hbkrg qr发起 QQ 机器人扫码登录（控制台二维码 + 扫码链接，扫码后凭据自动写入并连接；每次执行都会取消旧会话并输出全新二维码，二维码过期自动刷新重发、每次会话上限 3 次，超过后重新执行本命令即可）；凭据已配置时同样可用，扫码成功后替换现有凭据并以新凭据重连
/qq rebind玩家在游戏内自助解除自己的绑定，下次进服重新获取验证码
/qq qxqq <玩家名>管理员强制解除指定玩家的绑定
/qq skip <玩家名>把玩家加入跳过绑定名单（不再要求其绑定 QQ）
/qq unskip <玩家名>把玩家移出跳过绑定名单

安装教程

1创建机器人

  1. 在手机上安装 QQ 最新版本，点击 联系人 → 机器人 → 创建我的机器人
  2. 选择 其他服务，滚动到页面底部点击 "快速获取机器人 AppID 和 AppSecret"
  3. 设置头像、昵称和简介，把机器人的 ID 和 密钥 保存下来

电脑版高级创建：q.qq.com（QQ 机器人开放平台官网，与手机创建的机器人通用）

2安装并扫码登录（推荐）

  1. 从 下载页面 下载最新的 .jar 文件（插件版放 plugins/，模组版放 mods/）
  2. 启动服务器：未配置凭据时，启动约 30 秒后（等启动日志刷完）控制台会自动打印扫码登录二维码与扫码链接，手机 QQ 扫码（或复制链接到手机 QQ 打开）确认授权
  3. 授权成功后 AppID / Secret 自动写入配置文件并自动连接机器人，无需手动改文件；二维码过期会自动刷新重发新码（每次会话上限 3 次，超过后用 /hbkrg qr 手动重新发起）

备选（手动填写）：打开配置文件（插件版 plugins/KERONGPenguin/config.yml，模组版 kerongpenguin/config.yml）填入第 1 步保存的机器人信息后重启：

bot:
  app-id: '机器人ID'
  secret: '机器人密钥'
  name: '机器人名称'

3邀请机器人进群（自动绑定）

  1. 在 QQ 中把机器人邀请到你的群，点击机器人头像 → 设置
  2. 把 机器人可获取的信息范围 调成 群内全部消息，打开主动发消息开关
  3. 在群里发送任意消息（命令 / 聊天均可，如 /查信息）：bot.groups 未填写时插件自动把本群 OpenId 写入白名单并重载配置（含快捷面板同步），无需手动抄 ID、无需重启

之后要加别的群：自行把新群 OpenId 追加进 bot.groups（每一项必须用双引号包裹），或清空列表后让新群先发消息：

bot:
  groups: ["群A的OpenId", "群B的OpenId"]  # 留空 [] 时回到自动绑定模式

基础设置完成

在群里发送 /玩家名片、/查在线、/查性能 试试。机器人凭据可用扫码登录自动写入，也可手动填写重启生效；之后改其他配置执行 /hbkrg reload 即可（绝大多数配置即时生效，仅机器人凭据与更新检查两项必须重启，详见下方技术细节）。

基础设置已完成，其他功能配置请看常用设置

常用设置

日常使用看完上面三步就够了。这一节是 config.yml 里各配置项的说明——每个配置项一段示例加一段描述，要改什么直接查对应项即可。

机器人账号（bot 段）

bot.app-id 与 bot.secret 两个必填项见顶部安装教程第 2 步（推荐扫码登录自动写入；手动改凭据必须重启服务器）。

允许响应的群 bot.groups

bot:
  groups: ["群的OpenId"]  # 每项双引号；留空 [] = 自动绑定模式

填「群 OpenId」，不是群号！留空 [] 时为自动绑定模式：机器人拉进群后在群里发任意消息（命令 / 聊天均可），插件自动把该群 OpenId 写入本列表并重载配置（含快捷面板同步），无需手动抄 ID；绑定第一个群后其余群不再自动加入。要加别的群：把新群 OpenId 追加进列表（群里发 /查信息 可查到），或清空列表后让新群先发消息。改完 /hbkrg reload 生效。

多服务器集群 bot.cluster 段

bot:
  cluster:
    name: "生存服"          # 本服在按钮上显示的名称（留空则用 bot.name）
    members: ["生存服", "创造服"]  # 全部成员（含自己，各服必须一致）

多台服务器共用同一个 QQ 机器人（相同 AppID）时配置。配置后：群里执行命令先弹「选择服务器」按钮（按钮名就是对应的服务器名），按下后该群的命令、聊天转发与播报都由所选服务器处理；/切换服务器 指令可随时重新选择（QQ 快捷面板同步增加该按钮）。未配置（成员少于 2 个）时全部集群逻辑旁路，单服行为零变化。注意：各服的 members 列表必须完全一致，否则路由错乱。

机器人名称 bot.name

bot:
  name: "KERONGPenguin"  # 仅用于显示

消息与卡片上显示的机器人名，不影响功能。

断线重连提示 bot.reconnect-notify

bot:
  reconnect-notify: true  # false = 过程提示只写日志文件不刷控制台

控制台里断线重连的过程提示开关；机器人断线会自动重连，无需处理。

按钮互动冷却 bot.button-cooldown-seconds

bot:
  button-cooldown-seconds: 5  # 同一用户两次点按钮的最小间隔秒数，0 = 关闭

同一用户两次点击按钮（菜单 / 翻页 / 黑名单解除 / 切换服务器等全部按钮）的最小间隔，防止连点刷屏；间隔内的点击会被 QQ 提示「操作频繁」并且不执行。默认 5 秒，0 关闭；与图片命令的 render.command-cooldown-seconds 互不影响。改完 /hbkrg reload 即时生效。

服务器开关消息（server-notify 段）

开关与文案 server-notify

server-notify:
  enabled: true   # 总开关（默认开启）
  # 180 秒内再次开机判定为「重启」，超过按普通开机（0 = 不判定重启）
  restart-window: 180
  shutdown:
    enabled: true
    message: "[状态]\n服务器已正常关闭"   # 占位符：{server}、{platform}
  restart:
    enabled: true
    message: "[状态]\n服务器重启完毕，已正常运行(o‿∩)"
  start:
    enabled: true
    message: "[状态]\n服务器已开启！！(≧∇≦)/"
  crash:
    enabled: true
    message: "[状态]\n服务器...."

服务器关闭 / 重启 / 开机 / 意外关闭时向 QQ 群发送通知（只发给 bot.groups 里的群）：正常关闭发关机消息；上次正常关闭后 180 秒内（restart-window 可改）再次开机判定为重启，发「服务器重启完毕，已正常运行(o‿∩)」；超过 180 秒再开机按普通开机发开启消息；上次崩溃 / 强制结束后下次启动补发意外通知；首次安装不发送，插件重载不会误发。每类可独立开关改文案（配置文件里的修改真正生效）。

QQ 绑定（qq-bind 段）

绑定总开关 qq-bind.enabled

qq-bind:
  enabled: false  # true = 玩家进服必须先绑定 QQ 才能玩

开启后老玩家进服前直接拦截（验证码显示在「无法连接到服务器」界面），新玩家先放行建档再踢出展示验证码。玩家在群里直接发送纯数字验证码即可绑定（也可以发送 /绑定 验证码）。相关命令：/重新绑定（换号重绑）、/黑名单 @某人（管理员拉黑）。⚠ 开启前先关掉服务器自带白名单（white-list）——未绑定玩家会在白名单阶段先被拦下拿不到验证码，QQ 绑定本身就是准入控制，不要和白名单叠用。

Fabric 模组版的绑定不拦截进服：未绑定玩家正常游玩，绑定完全自愿——玩家在游戏内发送 /hbkrg qbd 获取验证码，再到 QQ 群发 /绑定 验证码（或直接发纯数字验证码）完成；qq-bind.enabled 在 Fabric 版只控制绑定功能开关，不拦截进服。

每 QQ 可绑定玩家数 qq-bind.max-players-per-qq

qq-bind:
  max-players-per-qq: 1  # 每个 QQ 最多绑几个玩家（只能填 ≥1）

默认 1 = 与旧版一样一个 QQ 只能绑一个玩家；调大后一个 QQ 可以绑多个（比如一个人两个号）。绑了多个玩家时，群里用玩家名片 / 重新绑定 / 签到这类指令，机器人会先列出名下全部玩家让你点击按钮选择（旧版 QQ 客户端不显示按钮时也可回复数字序号，2 分钟内有效；@机器人 发数字不会被当成 AI 对话）；玩家名片 @别人查询时对方多绑定同样弹按钮选择。已达上限时绑定码保留，解绑后重发同一码仍可绑定。填 0 / 负数按 1 处理；改完 /hbkrg reload 即时生效。

玩家名片开关 qq-bind.personal-info

qq-bind:
  personal-info: true  # false = 群里不再响应 /玩家名片

/玩家名片 玩家统计卡片命令的总开关。

验证码有效期与位数 code-expire-minutes / code-length

qq-bind:
  code-expire-minutes: 10  # 绑定码有效期（分钟）
  code-length: 5           # 绑定码位数（4-8）

绑定码多久过期、几位数字。

未绑定拦截界面文案 qq-bind.kick-message

qq-bind:
  kick-message:
    - "&c===== QQ 绑定验证 ====="
    - "&e你的专属绑定码: &a&l{code}"
    - "&7请在 QQ 群发送: &f{code}"

未绑定玩家进服看到的界面文案，一行一项（列表）；也可写成一行用 \n 分行（如 kick-message: "&c第一行\n&f第二行"）。支持 & 颜色代码，变量 {code} 绑定码 / {name} 玩家名 / {expire} 有效期分钟。完整默认文案见 config.yml。

每日签到（qq-bind.checkin 段）

签到开关与前缀 checkin.enabled / prefix

qq-bind:
  checkin:
    enabled: false   # 群里发 /签到
    prefix: "[签到]" # 签到成功回复的前缀

签到按天累计并记录连续天数；没装经济插件时照常累计、不发奖励。

金币奖励 checkin.reward

qq-bind:
  checkin:
    reward: 100.0  # 每次签到奖励的金币数

经 Vault 发放；未装 Vault 但装了 CoinsEngine 时改走 CoinsEngine。发放后按「前后余额差」校验到账，没到账会在回复里提示，不会悄悄吞掉。

点券奖励 checkin.points-reward

qq-bind:
  checkin:
    points-reward: 0  # 0 = 不发

经 PlayerPoints 发放，按 UUID 持久、离线玩家也能到账；装了才生效。

图片渲染（render 段）

玩家名片 / 查在线 / 查性能 / 排行榜的图片默认用内置背景图（随 JAR 自带，零配置即用）。以下各项改完 /hbkrg reload 立即生效。

查询结果缓存 render.result-cache-seconds

render:
  result-cache-seconds: 60  # 同一玩家查询结果复用秒数（0 = 每次重渲染）

多人频繁查询时避免重复渲染；0 = 不缓存。

头像缓存时长 render.avatar-cache-hours

render:
  avatar-cache-hours: 3  # 头像缓存小时数（0 = 不缓存）

玩家换皮肤想立即看到新头像就改小。渲染过的头像存在 cache/avatars/，重启不重复下载。

毛玻璃模糊度 render.blur-strength

render:
  blur-strength: 50  # 0-100，越大越模糊，0 = 不模糊

卡片背后背景的模糊程度（毛玻璃效果），默认 50 轻模糊。

标题框黑度 render.title-card-gray

render:
  title-card-gray: 80  # 0-255，越大越深

玩家名片 / 查在线 / 在线排行榜 / 查性能四张卡片顶部标题区的底色，默认 80 比项目卡片（106）略浅。

副标题灰度 render.subtitle-card-gray

render:
  subtitle-card-gray: 80  # 0-255，越大越深

玩家名片玩家名称项与五张卡片副标题条（服务器 / 更新时间 / 第三格：玩家名片 / 查在线 / 查性能为渲染耗时，排行榜（含财富榜）为展示玩家 TOP x 三张小卡）的底色，默认 80 与标题框相同。

自定义图片渲染线程 render.custom-render-threads（高级）

render:
  custom-render-threads:
    enabled: false        # 自定义开关（false = 自动模式，忽略下面两键）
    render-threads: 2     # 图片渲染线程数（1-16）
    avatar-threads: 8     # 头像批量下载线程数（1-16）

默认关闭（自动模式）：渲染线程按 CPU 核数自动取一半（1~4 条），头像批量下载 8 条——对绝大多数服务器是最优解。⚠ 警告：开启后线程数由你指定——渲染线程数越大，同时绘制的图片越多、CPU 争抢越强，核数少的服务器上可能影响游戏 tick，不建议超过物理核数的一半；头像下载线程是网络 IO 型（不占 CPU、不影响游戏 tick），调大主要是对外部头像接口的并发压力，调小则大名单收齐变慢。线程池在首次渲染时创建，修改本段后需重启服务器生效。

项目卡片黑度 render.item-card-gray

  item-card-gray: 106  # 0-255，越大越深

  reminder-mode: ""    # 留空 = 默认引用

技术细节与常见问题

这一节是给想深入了解或遇到问题的用户准备的，日常使用不需要看。

配置自动升级与注释保留

插件更新后首次启动，若配置文件版本低于新版内置版本，会自动以新版 config.yml 为底重建配置——全部注释、新增配置项都会更新到位，你改过的值原样保留。无需手动对照新配置改文件，也不会额外生成备份文件。

日常保存（如 /hbkrg bpngsz 一键切换背景写回配置）同样只改有变化的行，文件里的注释不会丢；万一某次保存无法安全保留注释，会退回整树写出（注释丢失但配置值不受影响，控制台会有提示）。

AppID / Secret 填了却鉴权失败

从网页或聊天窗口复制 AppID 常会把空格、零宽字符一起带进 config.yml（肉眼不可见），QQ 平台会直接拒绝（日志见 {"code":100007,"message":"appid invalid"}）。新版读取时会自动清洗首尾空白并提示；建议顺手把配置里的多余空白删掉。

机器人反复掉线 / 图片回复频繁失败

QQ 同一机器人只允许一条稳定连接。两台服务器填同一个 AppID 会互相挤占（轮流掉线、图片几乎必失败）。处理：关闭其中一台的机器人（bot.app-id 留空），或每台各申请一个机器人（免费）。机器人断线后自动重连，连续多次失败会暂停并在游戏内提示 /hbkrg chs 手动重试，或等 30 分钟自动重试。

在 QQ 群里远程执行 hbkrg chs（经 /执行命令）时，重连过程的关键节点（开始 / 成功 / 超时）会同步发回群里，不必盯着服务器控制台；自动重连不广播，不打扰群。

查性能卡片的指标细节

共五项：TPS（每秒刻数，满值 20，超过按 20 展示）/ MSPT（每刻耗时毫秒）/ 内存 / CPU / 在线人数（展示「当前 / 最大」，人数与最大值的来源见 render.performance.max-players-source——real = 真实值，motd = 服务器列表展示值（其他插件 / 模组改过的；插件按需本机自查询服务器列表取值，60 秒内复用，查不到回退真实值，插件版与模组版统一生效））。自动兼容 Spigot / Paper / Purpur / Folia / NeoForge 核心；Folia 多线程核心用插件内置采样器读取窗口均值。装了 Spark（插件 / 模组）时优先直接调用 Spark 取数（Paper 1.21+ 系核心已内置 spark，无需安装；想用自装版需加启动参数 -Dpaper.preferSparkPlugin=true，且 Modrinth 上的 spark 文件是模组变体、放 plugins 目录无效）；没装或读不到时回退自研采集，个别核心读不到时显示「--」。填了 TPS 变量时优先显示变量内容。为什么没有"延迟"项：玩家 Ping 反映的是客户端到服务器的连接往返，本地 / 同机 / 内网穿透部署下恒为 0ms，无监控意义。

头像显示与缓存

渲染过的头像保存在 cache/avatars/ 文件夹（重启不重复下载，过期自动清理）。获取统一走在线线路（各线路均带外层贴图）：MC-Heads → Minotar → MinePic → Crafatar → Mojang 官方 API（国内普遍超时排最后）→ 全部失败用占位块。批量获取（在线列表 / 排行榜等）多线程并行收齐；单轮最多等待 12 秒，超时的玩家先显示占位块，其下载在后台继续——完成后进缓存，下一轮查询自动补全真实头像。某玩家头像一直不显示时，看插件日志（logs/qq/）里记录的获取方式就能定位原因。玩家换皮肤想立即更新：调小 render.avatar-cache-hours。

哪些配置不能用 /hbkrg reload（只能重启服务器）

绝大多数配置改完执行 /hbkrg reload 立即生效：命令开关、群列表（bot.groups）、聊天转发格式、进出服 / 死亡播报、消息模板（Markdown 文件）、图片渲染设置（模糊度 / 缓存 / 冷却）、变量获取、AI 参数、签到设置等。只有以下两项 reload 不管用，改完必须重启服务器：

  • bot.app-id / bot.secret（QQ 机器人凭据）——QQ 客户端只在启动时用当期凭据连接一次，reload 和 /hbkrg chs 重连都不会读取新凭据。
  • update-check 段（更新检查）——只在服务器启动后第 8 秒检查一次新版本，改开关 / 镜像地址要下次启动才生效。

主命令：游戏内管理命令为 /hbkrg（旧名 /kerong、/hbkng 均已移除不兼容，输入旧命令会提示未知指令）。reload 会在重载配置后自动重新同步 QQ 快捷指令面板（先删除旧面板再按新配置重建按钮），改完命令开关执行一次 /hbkrg reload 即可，无需其他操作。

变量获取信息的生效范围与回退规则

variable-fetch 每个项目独立判定：变量留空 → 用插件自带数据；变量读取失败（未装 PlaceholderAPI / 变量不存在返回原文 / 返回空白）→ 自动回退插件自带数据。自定义项目读不到时不展示。生效范围：玩家名片卡片（各项目 + 自定义项目）、在线排行榜（玩家名 / 总在线时长）、财富榜（玩家名 / 金币）、查性能（TPS）；玩家名变量只改展示名，头像 / 统计 / 排名仍按真实玩家。变量解析在服务器主线程内一次完成（保证线程安全），解析结果（采用 / 回退）写进插件日志。模组版无 PlaceholderAPI 生态，恒用自带数据。

配置文件写错了语法

config.yml 写了非法语法（最常见是冒号后漏了空格）也能自愈：能自动修复的笔误直接修好写回；修不了的把原文件备份成 config.yml.error-时间戳 并重建默认配置继续启动，不会再出现"机器人不启动"的情况。

群里远程执行命令，控制台有记录吗

有。经 /执行命令 执行的每条命令与它的输出，都会以 [QQ 远程命令] 前缀同步写进服务器控制台和 latest.log，服务器运维侧看得到谁执行了什么；这些转发行不会再混回 QQ 回复（回复里只有命令本身的输出）。

插件版和模组版怎么选

插件版（Spigot）适用于 Spigot / Paper / Purpur / Folia / 混合端（Mohist、CatServer、Arclight 等）；模组版（NeoForge，MC 1.20.4+）放 mods/，需要 Java 21；Fabric 版放 mods/，MC 1.20.1 服务器用独立包 KERONGPenguin_Fabric-1.20.1，MC 1.20.4–1.21.x 用通用包 KERONGPenguin_Fabric-1.20.4（1.20.2/1.20.3 不适用）。各版本二进制不通用；自带 Bukkit 的混合端请用插件版。查询类命令的金币（Vault）、称号（DeluxeTags 或 PlayerTitle）、点券（PlayerPoints）没装对应插件时对应项目自动隐藏；财富榜在模组版或未装 Vault 的服务器上会提示未安装经济插件。PlayerTitle 称号与变量获取信息需要另装 PlaceholderAPI。

玩家数据存储

一个玩家一份 QUUID/<编号>.yml（绑定、签到、统计同文件），同名不同 UUID 视为两个人互不串数据，定时异步保存对性能几乎零影响。

基岩版互通（Geyser）

装了 Geyser-Spigot / Floodgate 的服务器，基岩玩家和 Java 玩家一样拿绑定码、绑定、签到、玩家名片，全部按玩家 UUID 记录；同名不同 UUID 即两个独立账号（基岩 .Steve 与 Java Steve 各自独立）。

内存占用说明

面板显示的是 JVM 预留量，不代表插件占用。游戏内发送 /hbkrg mem 可查看插件实际占用；插件在渲染空闲后会自动释放图像素材缓存，一般无需处理。
