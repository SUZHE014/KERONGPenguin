# 🤖 KERONG Penguin

> ⚠️ **此插件基于开源 QQ 机器人客户端方案深度定制**（源码已重写为可读的 Kotlin 工程）

Minecraft QQ 机器人插件，通过 QQ 官方机器人 API 实现 QQ 群与服务器的深度交互。

## 设计来源

- **图片渲染界面设计参考：BaiZhouziYou / 新亭泪**（设计来源：
  https://xintinglei.cn/，模板合集：
  https://github.com/BaizhouziYou/easybot-image-templates/）
  —— /查信息卡片、/查在线列表、排行榜的毛玻璃深色风格，早期版本参照
  该作者发布在 EasyBot 资源市场的图片模板复刻（见
  [issue #1](https://github.com/SUZHE014/KERONGPenguin/issues/1)）；
  /查性能卡片的液态玻璃样式（1.6.7.2）参考其
  EasybotServerPerformanceTemplate-WebGL 模板的液态玻璃主题；
  其后的分页、背景、头像渲染等为本项目的独立改进。

## 功能

- **QQ 绑定验证** — 玩家进入服务器前需绑定 QQ，5 位随机绑定码验证
- **个人信息统计卡片** — QQ 群发送 `/查信息`（1.5.2 前为 `/个人信息`），渲染深色卡片风格最多 9 项生涯统计卡片（金币/称号/在线时长/今日在线时长/累计签到/点券/屠龙次数/击杀玩家次数/死亡次数，依赖插件缺失的项自动隐藏，卡片高度自适应），背景默认内置深灰底图（随 JAR 分发，可在配置改为 img/ 目录随机图，1.5.7）；`/查信息 @成员` 可查询他人绑定的玩家信息（1.5.3）；`/查询open ID` 查询 OpenId，`/查询open ID <OpenId>` 反查该 OpenId 的 QQ 账号（群昵称 + 绑定玩家，1.5.3）
- **玩家统计自记录** — 实时累计游戏时长、击杀、死亡、挖掘、距离等数据，**按玩家 UUID** 记入各自 QUUID 主文件（一人一文件，1.5.3.1：同名不同 UUID 即两个人，互不串数据），定时异步保存，对性能几乎零影响
- **AI 对话** — QQ 群 @机器人 或服务器内输入前缀触发，支持 DeepSeek/OpenAI；群内回复引用发送者的原消息（1.5.3）
- **黑名单系统** — 管理员可将 QQ 加入黑名单，自动解绑并踢出
- **快捷指令面板** — QQ 群快捷指令菜单，根据配置动态显示
- **在线查询** — `motd.use-markdown` 开启时用 .md 模板渲染在线玩家列表；关闭时自动渲染深色风格在线列表图片（真实皮肤头像，人数多自动切长图，1.5.1）；`/查在线` 可用别名 `/在线`（1.6.0，不出现在快捷菜单）
- **在线 / 金币排行榜** — `/在线排行榜` 总在线时长排行、`/金币榜` 金币持有量排行（1.6.0，需 Vault），同一渲染器：排名徽章 + 皮肤头像 + 数值，超页自动分段发送
- **消息模板自定义** — 机器人每条群回复对应数据目录 Markdown/ 下一个 .md 模板文件（1.6.0，配置 messages 段可换文件与改文案，默认与旧版一字不差）
- **纯数字自动绑定** — QQ 绑定开启时群里直接发绑定码数字即完成绑定（1.6.0）；**经济别名** — economy-alias 配置后所有输出中的「金币」替换为自定义名称（1.6.0）
- **消息转发** — QQ 群 ↔ 游戏双向消息转发
- **自定义执行指令** — QQ 群触发自定义服务器命令
- **群内签到** — @机器人 /签到 领取金币奖励（需 Vault，离线暂存自动发放）

## 环境

- Java 21+（NeoForge 版）/ Java 17+（Spigot 版）
- **NeoForge 1.21.1**（server-NeoForge 模组版）或 Spigot / Paper / 混合端
  （Mohist、CatServer、Arclight 等，自动检测命令执行器）
- QQ 最新版（支持机器人功能）

> ✅ **支持 Geyser-Spigot / Floodgate 基岩版互通**：QQ 绑定、查信息、查在线、
> 排行榜、签到全部按玩家 UUID 记录，基岩玩家与 Java 玩家一致可用
> （同名不同 UUID 即两个独立账号，互不串数据；1.5.7.2 起金币入账也按
> 绑定记录里的真实 UUID 解析，基岩玩家离线领奖不再掉入名字派生的幽灵账户）。

> ⚠️ NeoForge 版与 Spigot 版二选一：**不要在自带 Bukkit 的混合端上安装模组版**（会与真 org.bukkit 冲突），混合端请用 Spigot 版。

## 从源码构建

```bash
# Spigot 版
./gradlew :server-Spigot:jar        # 编译两个模块
python3 scripts/package_jar.py       # 合成可分发的 fat JAR（可选）

# NeoForge 1.21.1 版
./gradlew :server-NeoForge:jar       # 编译模组模块（共用 common-Bot 源码）
python3 scripts/package_jar_neoforge.py  # 合成可分发的模组 JAR
```

> 依赖的第三方库（kloping QQ SDK、fastjson 等）以 `libs/deps.jar` 形式提供编译期引用，
> 打包时复用原版 JAR 中的依赖字节码；NeoForge 模块的编译期真实构件可用
> `python3 scripts/build_neoforge_libs.py` 一键重建
> （Minecraft mojmap 中间产物 + NeoForge / FML / bus 官方构件，详见
> `server-NeoForge/libs/README.txt`）。

## 项目结构

```
common-Bot/      # 机器人核心（QQ 客户端、群命令、状态持久化、QQ 绑定管理）
server-Spigot/   # Spigot 平台适配（主类、命令执行器、事件监听、配置管理、卡片渲染）
server-NeoForge/ # NeoForge 1.21.1 平台适配（org.bukkit 兼容层 + @Mod 主类 + 事件/命令/控制台执行）
```

> 同日覆盖版（4 项更新）：修复部分用户配置自动升级失败（bot.groups 只填

  服务器装了 [spark](https://spark.lucko.me/)（Spigot 端插件 / NeoForge
  端模组）时优先经其公开 API（反射调用，无编译依赖）读取 TPS（1 分钟
  平均）/ MSPT（10 秒均值）/ 进程 CPU（1 分钟均值）——Spark 对各核心
  的采集最稳（尤其 NeoForge 无 TPS 字段、纯 Spigot 无公开 API 的场合），
  装了就借它的数；没装、未加载或单项读不到时回退 1.6.7.1 的自研分层
  反射链，行为不变。
- **修复（覆盖版）：只填一个群时配置自动升级失败** —— 用户日志表现为
  `sequence entries are not allowed here`（groups: - XXX）+「配置重建放
  弃：合并结果校验未通过」：文本合并器把单元素列表误当标量拼到了键行
  尾（多元素列表不受影响，恰好漏过 1.6.7.2 原版冒烟）。现列表按类型

  感知（不再刷整段异常堆栈）。受影响的用户覆盖更新本版后重启即自动

- **调整（覆盖版）：移除液态玻璃样式** —— render.performance.style
  配置项与 liquid-glass 渲染分支整体移除（列表项随配置重建自动清理），
  查性能卡片固定原版毛玻璃深色样式（与其他卡片同源）。
- **新增（覆盖版）：全局透明度（render.global-opacity，默认 1.0）** ——
  作用于全部图片卡片（查信息 / 查在线 / 查性能 / 在线排行榜 / 财富榜）：

  60 秒）** —— 对应模板合集「关于渲染过慢问题」一节推荐开启的性能数据
  缓存：缓存窗口内的重复 /查性能 查询直接复用上一张卡片（多人同时查 /

### v1.6.7.1 更新日志（修复查性能 TPS/MSPT 读不到 / 删在线卡与显隐配置）

- **修复：/查性能 的 TPS / MSPT 一直显示「--」读不到** —— 根因：
  1.6.7 只反射了 Paper 系 API 的 getTPS() / getAverageTickTime()
  （纯 Spigot 核心没有这层 API），模组版反射的方法名又与
  NeoForge 1.21.1 实际类不符（运行时实为 getAverageTick
  TimeNanos() / tickTimesNanos，Mojang 映射名），导致插件版
  （纯 Spigot 核心）与模组版的 TPS / MSPT 永远拿不到。现改为
  PerformanceSnapshot 内建的分层兼容读取：① Paper / Purpur /
  Folia 的 Server 接口 API 层直接读；② 纯 Spigot 经
  CraftServer#getServer() 跳到内部 MinecraftServer 读
  recentTps 与 tickTimes 数组（1.20.4 Spigot 映射名与 1.20.5+
  Mojang 映射名双兼容）；③ 模组版读 getAverageTickTimeNanos
  （公有方法）失败再回退 tickTimesNanos / tickTimes 字段平均；
  ④ 仍读不到 TPS 时由 MSPT 换算（min(20, 1000/mspt)，与 Spark
  性能插件同款算法）——只要有 MSPT 就能给出 TPS。Spigot /
  Paper / Purpur / Folia / NeoForge 全系核心都能出数，逐层
  try 失败不影响后续层。
- **查性能卡片不再展示在线人数** —— 在线人数查在线命令已有专门
  卡片，性能卡专注 TPS / MSPT / 内存 / CPU 四项性能指标
  （2×2 固定四卡版式）；PerformanceSnapshot 删去 onlineCount /
  maxPlayers 字段。
- **移除 render.performance.show-* 单项显隐配置** —— 指标固定
  四项不再可隐藏，配置面精简：RenderSettings 删
  performanceItemEnabled，ConfigManager 删五个默认键并把
  show-* 收进废弃键迁移表（升级后旧配置残留自动清除，无需
  手动改），双端 config.yml 同步；查性能背景配置
  render.performance.builtin-background 保留。

### v1.6.6.4 更新日志（移除空闲 GC 提示与自动收缩：防全停顿卡顿）

- **移除：空闲 GC 提示（render.idle-gc-hint）与已提交堆自动收缩** ——
  空闲释放后向 JVM 发 System.gc 提示（及其后的「已提交超存活自动
  收缩」变体）都依赖 full GC 把 G1 扩张的堆归还操作系统，但 Full GC
  的全停顿实测 0.05~0.6 秒，且「无渲染」不等于服务器空闲——玩家
  正在游玩、跑图、打怪的任意时刻都可能撞上停顿，卡顿风险与内存
  回落的收益不成比例。1.6.6.4 起插件不主动触发任何 GC：内存归还
  交给 JVM 自然节奏，插件侧只做无停顿的确定性图像缓存释放（flush
  + 清空）。升级后旧配置残留的 render.idle-gc-hint 键自动清除
  （废弃键迁移机制），无需手动修改。
- **保持：启动期内存飙升的两项根治修复** —— ① 头像获取并发去重
  （单飞：同一玩家并发查询只有第一个真正走网络，其余等待共享结果，

  -Xmx——「启动时没占多少内存、一启动完内存狂增」的根因修复）；
  ② 渲染空闲内存释放（render.idle-release-minutes，默认 5 分钟，
  0 = 关闭）原样保留。
- **同步修正** —— /kerong mem 提示语不再声称「空闲释放时回落」；
  释放日志不再附 GC 提示开关状态。
