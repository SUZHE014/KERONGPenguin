# 🤖 KERONG Penguin

> ⚠️ **此插件基于开源 QQ 机器人客户端方案深度定制**（源码已重写为可读的 Kotlin 工程）

Minecraft QQ 机器人插件，通过 QQ 官方机器人 API 实现 QQ 群与服务器的深度交互。

## 设计来源

  <https://xintinglei.cn/>，模板合集：

  该作者发布在 EasyBot 资源市场的图片模板复刻（见

  /查性能卡片的液态玻璃样式（1.6.7.2 引入、1.6.7.2 覆盖版移除）参考其
  EasybotServerPerformanceTemplate-WebGL 模板的液态玻璃主题，1.6.7.5
  覆盖版起查性能卡面板透明度与其他卡片统一（半透明毛玻璃体系，
  整卡透明度由 render.global-opacity 全局控制）；
  其后的分页、背景、头像渲染等为本项目的独立改进。

## 功能

- **QQ 绑定验证** — 玩家进入服务器前需绑定 QQ，5 位随机绑定码验证
- **个人信息统计卡片** — QQ 群发送 `/查信息`（1.5.2 前为 `/个人信息`），渲染深色卡片风格最多 9 项生涯统计卡片（金币/称号/在线时长/今日在线时长/累计签到/点券/屠龙次数/击杀玩家次数/死亡次数，依赖插件缺失的项自动隐藏，卡片高度自适应），背景默认内置深灰底图（随 JAR 分发，可在配置改为 img/ 目录随机图，1.5.7）；`/查信息 @成员` 可查询他人绑定的玩家信息（1.5.3）；`/查询open ID` 查询 OpenId，`/查询open ID <OpenId>` 反查该 OpenId 的 QQ 账号（群昵称 + 绑定玩家，1.5.3）
- **玩家统计自记录** — 实时累计游戏时长、击杀、死亡、挖掘、距离等数据，**按玩家 UUID** 记入各自 QUUID 主文件（一人一文件，1.5.3.1：同名不同 UUID 即两个人，互不串数据），定时异步保存，对性能几乎零影响
- **AI 对话** — QQ 群 @机器人 或服务器内输入前缀触发，支持 DeepSeek/OpenAI；群内回复引用发送者的原消息（1.5.3）
- **黑名单系统** — 管理员可将 QQ 加入黑名单，自动解绑并踢出
- **快捷指令面板** — QQ 群快捷指令菜单，根据配置动态显示
- **在线查询** — `motd.use-markdown` 开启时用 .md 模板渲染在线玩家列表；关闭时自动渲染深色风格在线列表图片（真实皮肤头像，人数多自动切长图，1.5.1）；`/查在线` 可用别名 `/在线`（1.6.0，不出现在快捷菜单）
- **在线 / 金币排行榜** — `/在线排行榜` 总在线时长排行、`/金币榜` 金币持有量排行（1.6.0，需 Vault），同一渲染器：排名徽章 + 皮肤头像 + 数值，超页自动分段发送
- **消息模板自定义** — 机器人每条群回复对应数据目录 Markdown/ 下一个 .md 模板文件（1.6.0，配置 messages 段可换文件与改文案，默认与旧版一字不差）
- **纯数字自动绑定** — QQ 绑定开启时群里直接发绑定码数字即完成绑定（1.6.0）；**经济别名** — economy-alias 配置后所有输出中的「金币」替换为自定义名称（1.6.0）
- **消息转发** — QQ 群 ↔ 游戏双向消息转发
- **自定义执行指令** — QQ 群触发自定义服务器命令
- **群内签到** — @机器人 /签到 领取金币奖励（需 Vault，离线暂存自动发放）

## 环境

- Java 21+（NeoForge 版）/ Java 17+（Spigot 版）
- **NeoForge 1.21.1**（server-NeoForge 模组版）或 Spigot / Paper / 混合端
  （Mohist、CatServer、Arclight 等，自动检测命令执行器）
- QQ 最新版（支持机器人功能）

> ✅ **支持 Geyser-Spigot / Floodgate 基岩版互通**：QQ 绑定、查信息、查在线、
> 排行榜、签到全部按玩家 UUID 记录，基岩玩家与 Java 玩家一致可用
> （同名不同 UUID 即两个独立账号，互不串数据；1.5.7.2 起金币入账也按
> 绑定记录里的真实 UUID 解析，基岩玩家离线领奖不再掉入名字派生的幽灵账户）。

> ⚠️ NeoForge 版与 Spigot 版二选一：**不要在自带 Bukkit 的混合端上安装模组版**（会与真 org.bukkit 冲突），混合端请用 Spigot 版。

## 从源码构建

```bash
# Spigot 版
./gradlew :server-Spigot:jar        # 编译两个模块
python3 scripts/package_jar.py       # 合成可分发的 fat JAR（可选）

# NeoForge 1.21.1 版
./gradlew :server-NeoForge:jar       # 编译模组模块（共用 common-Bot 源码）
python3 scripts/package_jar_neoforge.py  # 合成可分发的模组 JAR
```

> 依赖的第三方库（kloping QQ SDK、fastjson 等）以 `libs/deps.jar` 形式提供编译期引用，
> 打包时复用原版 JAR 中的依赖字节码；NeoForge 模块的编译期真实构件可用
> `python3 scripts/build_neoforge_libs.py` 一键重建
> （Minecraft mojmap 中间产物 + NeoForge / FML / bus 官方构件，详见
> `server-NeoForge/libs/README.txt`）。

## 项目结构

```
common-Bot/      # 机器人核心（QQ 客户端、群命令、状态持久化、QQ 绑定管理）
server-Spigot/   # Spigot 平台适配（主类、命令执行器、事件监听、配置管理、卡片渲染）
server-NeoForge/ # NeoForge 1.20.4+ 平台适配（编译目标 1.20.4，向上兼容运行）（org.bukkit 兼容层 + @Mod 主类 + 事件/命令/控制台执行）
```

### v1.6.8 更新日志（时长单位小时化 / 排行榜头像修复）

> 1.6.8（2 项）：**在线时长最大单位改为小时**——「在线时长 / 总在线
> 时长」不再以「天」为最大单位展示（如 3天5时20分 现展示为 77时20分，
> 排行榜为 77小时20分钟），查信息卡片与在线排行榜同步调整；不足 1
> 小时仍展示到秒（查信息）/ 分（排行榜），「今日在线时长」本就以
> 小时为最大单位不变。**修复排行榜等大批量头像显示不出**——Mojang
> 官方头像线路（会话服务器直查 + 玩家名反查）从外置链路首位移到
> 最后兜底：官方线路国内服务器普遍超时（单玩家最多 3+5 秒），此前
> 排首位时排行榜 / 在线列表的并发预热预算（4 线程 × 8 秒）全部烧在
> 逐玩家等官方超时上，预算耗尽后整批头像被取消、显示占位块（官方
> 5 分钟冷却到期后又会重复烧一轮）；现外部多线路（MC-Heads →
> Minotar → MinePic → Crafatar，实测 0.4~5.8 秒）先行，官方 API 仅
> 在四条外部线路全部失败后才尝试，其余头像链路（本地皮肤数据 /
> 磁盘缓存 / 失败分类 / 单飞去重）不变。

### v1.6.7.11 更新日志（NeoForge 登录闸门挂载修复）

> 1.6.7.11（1 项）：修复 **NeoForge 模组版 QQ 绑定登录闸门挂载失败**——
> 服务器启动时日志出现「[QQ绑定] 登录闸门挂载异常（老玩家拦截退化为
> 加入后踢出）: … has @SubscribeEvent annotation, but takes an argument
> that is not valid for this bus」，且紧随其后又打印「登录闸门已挂载」
> 误导排查——闸门实际从未挂上，未绑定老玩家的拦截一直退化在「加入后
> 踢出」（绑定码常被「服务器连接失败」文字覆盖，可见性差）。根因：
> 1.6.7.9 重做的跨版本事件桥把监听器参数写成事件基类 `Event`，而 FML
> 的 mod 事件总线以 `IModBusEvent` 为标记类型构造，`EventBus` 校验监听
> 参数必须实现该接口，基类 `Event` 不满足，`register()` 直接抛
> `IllegalArgumentException`；且挂载方未检查结果，失败后照样报成功。
> 修复：不再使用注解监听，改为反射调用 `IEventBus.addListener(Class,
> Consumer)` 以「运行时探测到的具体配置阶段事件类」精确注册——
> MC 1.20.4 的 `OnGameConfigurationEvent` 与 1.20.6 / 1.21.x 的
> `RegisterConfigurationTasksEvent` 均实现 `IModBusEvent`、可正常通过
> 校验（已对 20.4.253 / 20.6.144 / 21.1.252 / 21.11.48 构件字节级
> 核对，该 addListener 重载在 bus 7.x / 8.x 签名一致），且只收到该
> 事件本身无需基类过滤；`registerTo` 改为返回真实结果，「已挂载」
> 提示只在成功时输出，失败场景（未识别事件形态 / 总线缺少
> addListener 重载 / 任何异常）均有如实 WARN 与降级说明；增加幂等
> 护栏防集成服多世界重复挂载。Spigot 插件版行为不变，随版本号同步
> 发版；冒烟补上真实 mod 总线端到端注册 + 分发测试（本次漏网根因）。
