# 🤖 KERONG Penguin

> ⚠️ **此插件是 HuHoBot 的魔改分支**（源码已按 HuHoBot 上游结构重写为可读的 Kotlin 工程）

Minecraft QQ 机器人插件，通过 QQ 官方机器人 API 实现 QQ 群与服务器的深度交互。

## 功能

- **QQ 绑定验证** — 玩家进入服务器前需绑定 QQ，5 位随机绑定码验证
- **个人信息统计卡片** — QQ 群发送 `/查信息`（1.5.2 前为 `/个人信息`），渲染深色卡片风格最多 9 项生涯统计卡片（金币/称号/在线时长/今日在线时长/累计签到/点券/屠龙次数/击杀玩家次数/死亡次数，依赖插件缺失的项自动隐藏，卡片高度自适应），背景默认内置深灰底图（随 JAR 分发，可在配置改为 img/ 目录随机图，1.5.7）；`/查信息 @成员` 可查询他人绑定的玩家信息（1.5.3）；`/查询open ID` 查询 OpenId，`/查询open ID <OpenId>` 反查该 OpenId 的 QQ 账号（群昵称 + 绑定玩家，1.5.3）
- **玩家统计自记录** — 实时累计游戏时长、击杀、死亡、挖掘、距离等数据，**按玩家 UUID** 记入各自 QUUID 主文件（一人一文件，1.5.3.1：同名不同 UUID 即两个人，互不串数据），定时异步保存，对性能几乎零影响
- **AI 对话** — QQ 群 @机器人 或服务器内输入前缀触发，支持 DeepSeek/OpenAI；群内回复引用发送者的原消息（1.5.3）
- **黑名单系统** — 管理员可将 QQ 加入黑名单，自动解绑并踢出
- **快捷指令面板** — QQ 群快捷指令菜单，根据配置动态显示
- **在线查询** — `motd.use-markdown` 开启时用 .md 模板渲染在线玩家列表；关闭时自动渲染深色风格在线列表图片（真实皮肤头像，人数多自动切长图，1.5.1）；`/查在线` 可用别名 `/在线`（1.6.0，不出现在快捷菜单）
- **在线 / 金币排行榜** — `/在线排行榜` 总在线时长排行、`/金币榜` 金币持有量排行（1.6.0，需 Vault），同一渲染器：排名徽章 + 皮肤头像 + 数值，超页自动分段发送
- **消息模板自定义** — 机器人每条群回复对应数据目录 Markdown/ 下一个 .md 模板文件（1.6.0，配置 messages 段可换文件与改文案，默认与旧版一字不差）
- **纯数字自动绑定** — QQ 绑定开启时群里直接发绑定码数字即完成绑定（1.6.0）；**经济别名** — economy-alias 配置后所有输出中的「金币」替换为自定义名称（1.6.0）
- **消息转发** — QQ 群 ↔ 游戏双向消息转发
- **自定义执行指令** — QQ 群触发自定义服务器命令
- **群内签到** — @机器人 /签到 领取金币奖励（需 Vault，离线暂存自动发放）

## 环境

- Java 21+（NeoForge 版）/ Java 17+（Spigot 版）
- **NeoForge 1.21.1**（server-NeoForge 模组版）或 Spigot / Paper / 混合端
  （Mohist、CatServer、Arclight 等，自动检测命令执行器）
- QQ 最新版（支持机器人功能）

> ✅ **支持 Geyser-Spigot / Floodgate 基岩版互通**：QQ 绑定、查信息、查在线、
> 排行榜、签到全部按玩家 UUID 记录，基岩玩家与 Java 玩家一致可用
> （同名不同 UUID 即两个独立账号，互不串数据；1.5.7.2 起金币入账也按
> 绑定记录里的真实 UUID 解析，基岩玩家离线领奖不再掉入名字派生的幽灵账户）。

> ⚠️ NeoForge 版与 Spigot 版二选一：**不要在自带 Bukkit 的混合端上安装模组版**（会与真 org.bukkit 冲突），混合端请用 Spigot 版。

## 从源码构建

```bash
# Spigot 版
./gradlew :server-Spigot:jar        # 编译两个模块
python3 scripts/package_jar.py       # 合成可分发的 fat JAR（可选）

# NeoForge 1.21.1 版
./gradlew :server-NeoForge:jar       # 编译模组模块（共用 common-Bot 源码）
python3 scripts/package_jar_neoforge.py  # 合成可分发的模组 JAR
```

> 依赖的第三方库（kloping QQ SDK、fastjson 等）以 `libs/deps.jar` 形式提供编译期引用，
> 打包时复用原版 JAR 中的依赖字节码；NeoForge 模块的编译期真实构件可用
> `python3 scripts/build_neoforge_libs.py` 一键重建
> （Minecraft mojmap 中间产物 + NeoForge / FML / bus 官方构件，详见
> `server-NeoForge/libs/README.txt`）。

## 项目结构

```
common-Bot/      # 机器人核心（QQ 客户端、群命令、状态持久化、QQ 绑定管理）
server-Spigot/   # Spigot 平台适配（主类、命令执行器、事件监听、配置管理、卡片渲染）
server-NeoForge/ # NeoForge 1.21.1 平台适配（org.bukkit 兼容层 + @Mod 主类 + 事件/命令/控制台执行）
```

### v1.6.3 更新日志（插件与模组同步发版：双服同绑实锤检测 / 模组日志格式 / 死代码瘦身）

- **修复：两台服务器绑同一个机器人仍能同时运行**（如 NeoForge + Spigot
  各一台填同一 AppID）—— 1.6.2 的互踢检测只覆盖连接层（短命会话互踢
  / 鉴权期被关），抓不到实测存在的第三种形态：**两台同时在线、同时
  收到并处理同一条群消息、各自回复**。被动回复的去重键是
  （msg_id, msg_seq），两台服务器的回复序号都从 1 开始，先到的被受理、
  后到的被 QQ 按 40054005「消息被去重」拒收——图片（渲染耗时、总是
  后发）几乎每条都失败，这正是 1.6.0/1.6.1「回复图片消息失败」的
  真正根因（当时误判为网关重投递；1.6.2 的 ReplySeqGuard 按重投递
  修复，保住了同服重投递场景但治不了双服）。现新增消息级检测
  ConflictWatch：本进程回复序号经 ReplySeqGuard 保证不重复，被去重
  拒收的唯一解释是**另一个客户端抢先回复了同一条消息**——10 分钟内
  3 次即判定成立，醒目输出原因与处理方法并**断开本服机器人、停止
  自动重连**（继续在线只会互抢消息；配置错误重试无意义，不走 30
  分钟轮次），管理员处理后用 /hb chs 恢复；服务器本体不受影响。
- **修复：第二台服务器鉴权阶段被拒时毫无冲突提示** —— 旧版互踢
  证据只统计「鉴权成功后短命被关」，鉴权期被关的连接（Identify/
  Resume 被拒）只当普通失败重连，第二台服务器只有「第 N 次（1/5）
  重试连接…」和无原因的「重连超时」。现凭据自检（QqTokenHealth，
  lastCheckOk）通过时，鉴权期被关也计入互踢证据窗口：凭据有效却
  连不上 = 网关拒绝本连接，指向同 AppID 被另一台服务器占用。
- **修复：模组版控制台出现原始格式日志**（`Oct 13, 2026 11:41:13 PM
  cn.huohuas001…ConfigManager reload / INFO: …`，无 [KERONGPenguin/]
  前缀）—— 兼容层 JavaPlugin.logger 原为裸 java.util.logging，NeoForge
  无 JUL 桥接。现挂 JUL→SLF4J 转发 Handler（幂等、父级输出关闭），
  共享源码（ConfigManager / QqBindManager）输出与 Spigot 版同为标准
  [KERONGPenguin/]: 格式；QqBindManager 构造期「已就绪」行不再走
  println（旧版在 NeoForge 下显示为 [STDOUT/] 原始格式）。
- **修复：/motd <host> 带参数查其他服务器不可用** —— PublicCommands
  先注册且命令分发首个匹配即短路，MotdCommands（minebbs 远程状态
  查询 + motd-* 五个模板）实际永不可达（旧注释声称会转发但没有实现）；
  现 PublicCommands.motd 带参数时真正委托 MotdCommands。
- **清理：死代码移除与依赖瘦身** —— 删除零引用的 Kotlin 声明 21 项
  （CollectionUtils / HReflection / WebUiPassword / WhiteList 死链 /
  sendWithMention / executeCustomCommand / getCommandTrigger /
  NeoScheduledHandle 等）；打包剔除运行时永不加载的第三方库
  （c3p0 / HikariCP / terracotta —— 仅 Quartz JDBC JobStore SPI 反射
  加载，SDK 用 RAMJobStore；webui/ schema/ 残留资源），双端 JAR 各
  减小约 1.3 MB（Spigot 20.3→19.0 MB，NeoForge 19.6→18.3 MB）。
- 保留：ReplySeqGuard（1.6.2 去重基数修复）——网关弱网/会话恢复重投递
  同一消息到**本服**时序号不重复的防护仍然有效，且使 40054005 成为
  双服务器冲突的可靠信号。

### v1.6.2 更新日志（插件与模组同步发版：回复去重修复 / 重连体系 / 更新检查 / 财富榜）

- **修复：回复图片消息失败（QQ 返回 code 40054005"消息被去重，请检查请求 msgseq"）** ——
  根因：QQ 群机器人被动回复按（msg_id, msg_seq）去重，同一消息的多条回复必须
  使用不同的 msg_seq；SDK 在事件对象内维护自增序号（从 1 起），但 QQ 网关在
  弱网 / 会话恢复时会**重投递同一条群消息**，SDK 为其创建全新事件对象——
  序号又从 1 起算，与首次投递的回复序号重复，被平台按重复消息拒收
  （分页排行第二张图起最易触发）。现每条消息到达时按 msg_id 分配互不
  重叠的回复序号基数（重投递跳开 100000），任何两条回复的 msg_seq
  不会重复；基数按 msg_id 隔离、30 分钟自动清理，内存开销可忽略。
- **新增：机器人断线重连全程可见（ReconnectManager 重连编排）** ——
  SDK 每发起一次重连，控制台输出"第 N 次（1/5）重试连接…"；连接恢复并
  健康存活后输出"重连成功"；连续 5 次重连失败（重连超时）暂停自动重连
  并提示：可使用指令 **/hb chs** 立即手动重试，或等待 30 分钟后自动进行
  下一轮（最多 3 轮）。重试过程提示可在配置 `bot.reconnect-notify`
  关闭（防刷屏），但"重连超时 + /hb chs 恢复指引"的失败提示不可关闭。
- **修改：两台服务器绑定同一个机器人不再直接停止运行** —— 1.6.1 判定
  互踢后会完整停机（机器人不响应、只能重启恢复）；1.6.2 起改为醒目
  提示原因（"已有另一台服务器绑定了同一个机器人"）后继续走统一的
  5 次 × 3 轮重试体系，服务器本体与插件其余功能不受影响；单次短命
  连接即输出醒目提示（修复旧版第二台服务器启动时控制台毫无明确
  提示的问题）。
- **新增：/hb chs 手动重连命令**（Spigot /huhobot chs 与 /hb chs 均可）——
  重连超时挂起或断线期间随时使用：重置重连计数并立即恢复连接
  （等价于 30 分钟退避结束后的自动重试）。
- **新增：更新检查（update-check.enabled，默认开启）** —— 插件启动后
  异步访问官网版本文件（kerong.xin/penguin/version.json）：有新版本时
  控制台输出最新版本号、下载页链接与简要更新日志；已是最新输出一行
  提示；检测失败只输出一句话（不刷屏），异常细节写入插件日志文件。
- **更名：/金币榜 → /财富榜** —— 快捷菜单按钮同步更名；旧命令
  /金币榜 保留为隐藏别名（与主命令共用开关，不占菜单位）；升级时
  commands.金币榜 的开关取值自动迁移到 commands.财富榜
  （config-version 17→18）；消息模板文件名仍为 coins-leaderboard-*.md，
  已自定义模板的用户升级后不丢失。
- **修复：极少数玩家头像始终无法获取** —— 两处根因：① 名字反查
  Mojang 接口遇到限流（429）/网络抖动时，旧版把"本次查询失败"当作
  "名字无正版账号"写入**永久**负缓存，这些玩家从此头像永远失败
  （排行榜并发预热最易触发限流）；现区分处理——429/网络异常不写
  负缓存（下次自动重试），404 才写且仅 30 分钟有效。② Mojang 极少数
  老账号的 UUID 非 v4（如 v3），旧版两层条件全部跳过导致头像永远
  失败；现名字反查到正版 UUID 即查询会话服务器。

### v1.6.1 更新日志（插件与模组同步发版：图片发送误报 / 双服互踢检测 / 日志留档）


- **修复：图片已发出但仍提示"图片发送失败（机器人连接可能断开）"** ——
  根因：QQ 群富媒体（图片）消息接口普遍 10 秒以上才返回应答，而 SDK
  内置 OkHttp 读超时硬编码 10 秒——请求实际已送达 QQ 并投递了图片，
  客户端却先超时抛异常，旧版一律按失败提示。现对异常分类：读超时
  （请求已发出、图片大概率已投递）只记 WARNING 日志、不再提示失败；
  连接 / 上传等未送达异常仍提示重试。同时校验 QQ 应答码 ret
  （200 与 2022021x"已受理"均视为成功）。
- **修复：两台服务器填同一个机器人（AppID/Secret）都"能跑"的问题** ——
  QQ 同一机器人只允许一条网关连接，双服会自动重连互踢（轮流掉线、
  消息随机丢失，表面看两台都在运行）。现检测互踢特征（连接鉴权成功
  后连续 3 次在数秒内被平台关闭），判定后停止本服务器的机器人连接
  并输出明确失败原因：已有另一台服务器绑定了同一机器人；修正配置
  （每台服务器用独立机器人凭据）后重启即可恢复。
- **控制台输出去掉重复时间戳** —— "[KERONGPenguin] [2026-10-13 20:38:46]"
  里的插件自拼时间戳删除（服务端控制台本就按行输出时间）；日志文件行
  保留时间戳不受影响。
- **控制台全部输出保存到日志** —— info 级控制台输出（启动 / 模板释放 /
  面板同步等）与警告、错误一致双写插件日志文件（logs/qq/qq-bind-日期.log，
  混合端 latest.log 路由不稳也不丢）；签到经济检测等三处彩色控制台提示
  同步入档，文件行自动剥离 § 颜色代码。
- **经济别名覆盖补全** —— QQ 快捷面板按钮描述（"金币数量排行" /
  "每日签到领金币"）跟随 economy-alias 替换（金币榜图片标题、查信息卡片
  金币项、消息模板出口 1.6.0 已覆盖）。
- **模板变量全量文档化** —— config.yml messages 段新增占位符总注释
  （每个变量一行含义说明，含 {player}/{reward}/{streak}/{lastSeenPart}/
  {protocolLine}/{playersSection} 等全部 26 个变量），官网教程同步变量表。
- **文档** —— 配置注释与官网教程移除"指令重载配置"字段说明（修改配置
  一律重启服务器生效）。
