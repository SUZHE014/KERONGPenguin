# 🤖 KERONG Penguin

> ⚠️ **此插件是 HuHoBot 的魔改分支**（源码已按 HuHoBot 上游结构重写为可读的 Kotlin 工程）

Minecraft QQ 机器人插件，通过 QQ 官方机器人 API 实现 QQ 群与服务器的深度交互。

## 功能

- **QQ 绑定验证** — 玩家进入服务器前需绑定 QQ，5 位随机绑定码验证
- **个人信息统计卡片** — QQ 群发送 `/查信息`（1.5.2 前为 `/个人信息`），渲染毛玻璃风格最多 9 项生涯统计卡片（金币/称号/在线时长/今日在线时长/累计签到/点券/屠龙次数/击杀玩家次数/死亡次数，依赖插件缺失的项自动隐藏，卡片高度自适应），支持多张背景图随机切换；`/查信息 @成员` 可查询他人绑定的玩家信息（1.5.3）；`/查询open ID` 查询 OpenId，`/查询open ID <OpenId>` 反查该 OpenId 的 QQ 账号（群昵称 + 绑定玩家，1.5.3）
- **玩家统计自记录** — 实时累计游戏时长、击杀、死亡、挖掘、距离等数据，一人一文件（QUUID/stats/，1.5.3.1）定时异步保存，对性能几乎零影响
- **AI 对话** — QQ 群 @机器人 或服务器内输入前缀触发，支持 DeepSeek/OpenAI；群内回复引用发送者的原消息（1.5.3）
- **黑名单系统** — 管理员可将 QQ 加入黑名单，自动解绑并踢出
- **快捷指令面板** — QQ 群快捷指令菜单，根据配置动态显示
- **在线查询** — `motd.use-markdown` 开启时用 .md 模板渲染在线玩家列表；关闭时自动渲染毛玻璃风格在线列表图片（真实皮肤头像，人数多自动切长图，1.5.1）
- **消息转发** — QQ 群 ↔ 游戏双向消息转发
- **自定义执行指令** — QQ 群触发自定义服务器命令
- **群内签到** — @机器人 /签到 领取金币奖励（需 Vault，离线暂存自动发放）

## 环境

- Java 17+
- Spigot / Paper / 混合端（Mohist、CatServer、Arclight 等，自动检测命令执行器）
- QQ 最新版（支持机器人功能）

## 从源码构建

```bash
./gradlew :server-Spigot:jar   # 编译两个模块
python3 scripts/package_jar.py # 合成可分发的 fat JAR（可选）
```

> 依赖的第三方库（kloping QQ SDK、fastjson 等）以 `libs/deps.jar` 形式提供编译期引用，
> 打包时复用原版 JAR 中的依赖字节码。

## 项目结构

```
common-Bot/      # 机器人核心（QQ 客户端、群命令、状态持久化、QQ 绑定管理）
server-Spigot/   # Spigot 平台适配（主类、命令执行器、事件监听、配置管理、卡片渲染）
```

## 版本

当前版本：**1.5.3.1**

### v1.5.3.1 更新日志

- **优化：查信息统计记录一人一文件** —— 全部玩家合一的 stats.yml 迁移到
  QUUID/stats/<玩家UUID>.yml，彻底消除单文件随玩家数增长膨胀的风险；
  启动零装载（进服 / 查询到该玩家时才读他那一个小文件），保存只写
  **有变动**的玩家文件（脏标记：5 分钟周期 + 退出 + 关服），未变动的
  玩家零磁盘 IO；旧版 stats.yml 首次启动自动拆分迁移并归档
  （stats.yml.migrated，一次性备份不再增长），迁移失败下次启动自动重试
- **优化：OpenId 目录一人一文件** —— openids.yml 迁移到
  QUUID/openid/<OpenId>.yml，同样消除单文件膨胀风险；查询懒加载、
  落盘只写有变动的 OpenId 文件（2 分钟低优先级守护线程 + 退出兑底），
  旧版 openids.yml 首次访问自动迁移归档
- **修复：无称号玩家称号栏显示英文串** —— 玩家没有称号时不再回退显示
  Vault 主权限组名（default/member 等英文串），一律显示“暂无”

### v1.5.3 更新日志

- **修复：机器人掉线死循环（诊断钩子拦截 SDK 协议处理）** ——
  反编译 SDK 确认 kloping WebSocketListener 的返回值约定为“返回 false = 拦截”；
  1.5.3 首版诊断钩子全部返回了 false，导致 SDK 收到 Hello 后不再发送鉴权包，
  平台 60 秒超时踢线（1006/4009）→ 重连 → 再踢的死循环；
  现钩子改为纯观察者全部放行，鉴权、心跳、SDK 自动重连链路完整恢复
- **修复：连接错误堆栈不落盘** —— SDK 的 onError 原本只输出“wss error”
  （异常堆栈仅进控制台），现在异常类型 + 消息 + 完整堆栈前 15 帧直接写入
  插件日志文件，协议关键帧（Hello/READY/Invalid Session/鉴权包/连接关闭）
  同步落盘，事后可完整还原鉴权对话
- **新增：心跳自愈** —— SDK 心跳停跳超 1.5 倍心跳间隔时插件代发 op 1 心跳；
  心跳已发但平台连续 3 个周期无应答（连接假死）时主动重连恢复，
  不再干等平台 4009 踢线或底层 86 秒断线检测
- **新增：鉴权失败快速恢复** —— Hello 后 60 秒仍无 READY 主动重连重鉴权
  （90 秒限频防重连风暴）；启动时对 AppID 凭据做健康自检
  （与 SDK 同源 token 接口），凭据失效直接给出明确日志提示
- **新增：`/帮助` Markdown 重排版** —— 帮助输出改用 Markdown 格式
  （标题 / 加粗 / 列表 / 分隔线），末行显示当前插件版本
- **优化：诊断钩子极低开销** —— 业务事件帧不再逐帧 JSON 解析、不落盘
  （廉价字符串扫描 + 内存计数），心跳与应答不落盘（仅时间戳），
  看门狗为单守护最低优先级线程（10 秒一次 volatile 检查）；
  后台诊断常驻开销可忽略，日志文件只保留协议关键帧
- **新增：AI 对话引用回复** —— 群内 @机器人 提问后，AI 的回复会**引用发送者的原消息**
  （QQ 官方 MessageReference 协议，新事件取 MessageScene 的 msg_idx，
  旧协议自动回退）；平台不支持引用时自动回退普通回复，AI 回复不会丢失
- **新增：`/查信息 @成员`** —— 查询该成员 QQ 绑定的玩家统计卡片；
  未绑定时提示“该成员未绑定”（查询冷却按发起者计，防止代刷）
- **新增：`/查询open ID <OpenId>` 反查** —— 显示该 OpenId 对应的 QQ 账号
  （群昵称、最后活跃时间、绑定玩家）；群昵称由插件从群消息中积累的
  OpenId 目录提供（QUUID/openid/ 一人一文件持久化，1.5.3.1）
- **优化：信息卡依赖自适应** —— Vault（金币）/ DeluxeTags（称号）/ PlayerPoints（点券）
  未安装或未启用时对应统计项**不再显示“暂无/未启用”，直接隐藏该项**；
  签到未开启同理隐藏“累计签到”；卡片高度随实际项数自适应，底部不再留白

### v1.5.1 更新日志

- **修复**：称号还是无法检测（MC 1.8.x 等老版本服务器）—— 老版 DeluxeTags（2015-2021 全系）
  的标签查询是 `DeluxeTag` 类的**静态方法**，主类没有 `getTagsHandler()`，此前所有反射
  查询均落空；现按“新版实例 API → 老版静态 API → PlaceholderAPI 占位符”三层
  依次尝试，任何 DeluxeTags 版本都能取到称号
- **新增**：称号 / 点券 / 金币检测日志 —— 每次 `/个人信息` 查询把三项检测的来源与结果
  写入插件日志文件（如 `DeluxeTags(老版静态API)` / `Vault` / `PlayerPoints`，失败时附原因），
  排障直接翻日志即可定位
- **简化**：查在线配置 —— 移除 `motd.text` 文本模板与 `query-online.image-output` 配置：
  `motd.use-markdown` 开启时走 Markdown 模板；关闭时自动改用渲染图片输出
  （毛玻璃卡片 + 真实皮肤头像 + 长图，无需任何配置）
- **优化**：内存限制 —— 背景缓存由“仅张数上限”改为“张数 + 总字节预算（36MB）双限制”，
  超预算按最久未使用淘汰；长图背景不再按整幅画布高度处理，改为高度封顶后拉伸铺满；
  背景模糊与暗化合并为单遍合成，处理峰值内存减半
- **优化**：全链路异步 —— `/个人信息` 与 `/查在线` 的消息线程只做冷却判断，
  绑定查找（磁盘 IO）、主线程数据采集、头像预热、渲染与发送全部在渲染池执行；
  主线程数据读取由 4 次独立跳转合并为 1 次
- **优化**：查在线图片背景同样从 `img/` 目录随机选取（与个人信息卡共用），
  任意尺寸图片自动裁剪 / 拉伸铺满

### v1.5.0 更新日志（含 1.4.5 → 1.5.0 全部更改）

**本次修复 / 新增（1.5.0）**

- **修复**：信息卡片图片有概率加载失败 —— 背景图缩放的浮点截断会使裁剪区域越界
  （`RasterFormatException`），随机背景下偶发卡片生成失败；现改为向上取整并保证
  裁剪恒在图像范围内，任何尺寸背景图均稳定生成
- **修复**：称号无法检测 —— DeluxeTags 对接改为宽容反射（按方法名匹配并自适应参数
  类型，兼容不同版本的 API 重载）；在线玩家直接取游戏内实际显示的标签（含默认 /
  强制 / 玩家自选），离线玩家回退到持久化保存的选择；称号里的占位符文本自动剔除
- **新增**：统计项 **累计签到**（本插件签到系统的累计次数）与 **点券**
  （PlayerPoints 插件点券余额；未检测到相关插件时显示“未启用”）
- **新增**：/查在线 图片输出（1.5.0 首次引入 `query-online.image-output` 开关，
  1.5.1 起改为 markdown 关闭时自动启用）—— 按用户模板
  渲染毛玻璃风格在线列表卡片（含真实皮肤头像、服务器 / 更新时间 / 状态栏、
  3 列玩家网格）；玩家较多时自动切换为长图发送（高度随人数加长，一图展示全部）
- **优化**：图片渲染 CPU 占用硬编码上限（不走配置文件）—— 全部图片渲染共用
  专用线程池，线程数固定为 **主机核数一半（1~4 线程）**：既不像单线程限流那样
  排队堆积，也不会高并发时占满 CPU；空闲线程 60 秒自动回收
- **优化**：渲染完成后释放 JVM 内存 —— 单次渲染画布立即 flush 释放栅格，
  并做节流 GC 提示（两次至少间隔 60 秒，`qq-bind.render.gc-after-render` 可关）；
  渲染中的临时内存（背景解码 / 画布栅格 / PNG 编码缓冲）均为一次性对象，
  渲染结束即成垃圾由 GC 自动回收，不会永久驻留
- **优化**：同一玩家在 `qq-bind.render.result-cache-seconds`（默认 60 秒，0 关闭）内
  重复查询直接复用上次渲染的图片，零渲染开销秒回；配合单用户 5 秒查询冷却、
  背景 / 头像缓存，连续查询不再拉高 CPU 与内存
